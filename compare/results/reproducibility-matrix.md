# Reproducibility Matrix

This document defines what `alea` treats as reproducible output. It is part of
the core RNG roadmap and is intended to prevent accidental compatibility breaks.

## Stable Outputs

These APIs are expected to produce the same outputs for the same inputs across
Zig 0.16 builds on supported 64-bit targets unless a versioned breaking change
is explicitly documented.

| Area | Stable contract |
| --- | --- |
| `Seed.fromBytes`, `Seed.fromString`, `Seed.mix`, `Seed.stream`, `Seed.fromRng` | Same `u64` seed state for identical input bytes, stream indexes, or source RNG stream; `Seed.fromRng` consumes one `u64` seed draw. |
| `SplitMix64.next` | Same `u64` sequence for identical seed. |
| `Alea4x64.next` / `fill` | Same byte stream for identical seed. |
| `Wyhash64.next` / `fill` | Same byte stream for identical seed. |
| `Xoshiro128PlusPlus.nextU32`, `nextU64`, and `fill` | Same stream for identical seed; `nextU64` combines two `nextU32` draws in little-endian order, matching local Rust `rand_core::utils::next_u64_via_u32`. |
| `Xoshiro256.next`, `jump`, `longJump`, `split` | Same stream transitions for identical seed and operation order. |
| `Xoshiro256PlusPlus.next`, `jump` | Same stream transitions for identical seed and operation order. |
| `Pcg64.next` / `initTwo` | Same stream for identical seed and stream id. |
| `StepRng.next` / `fill` | Same arithmetic `u64` sequence and little-endian byte stream for identical initial value and increment; increment 0 is a constant stream. |
| Root Rust-discoverable engine names including `Xoshiro128PlusPlus`, `ChaCha8Rng`, `ChaCha12Rng`, `ChaCha20Rng`, `StdRng`, and `SmallRng` | Same output as their concrete or alias targets for identical seeds. Current mappings: `ChaCha12Rng = ChaCha`, `StdRng = SecurePrng = ChaCha12`, and `SmallRng = Xoshiro256PlusPlus` on local 64-bit Linux; `Xoshiro128PlusPlus`, `ChaCha8Rng`, and `ChaCha20Rng` are concrete portable named streams. |
| Engine `fromRng` / `fork` helpers | Same child engine stream for identical source engine stream; direct-engine `fromRng` / `fork` consume enough `u64` seed material to fill each target engine's state or key. |
| `Rng.ReseedingRng(Engine)` | Same output for identical initial engine seed, reseeder stream, and `reseed_threshold`: exactly `reseed_threshold` engine draws (or the equivalent bytes) are emitted before the engine is replaced with `Engine.seedFromU64(reseeder.nextU64())`; `nextU32` mirrors the wrapped engine when it exposes one, and byte fills never cross a reseed boundary. |
| `Rng.ReaderRng` | Same output for an identical reader byte stream: `next`/`nextU64` consume eight little-endian bytes, `nextU32` consumes four, and `fill` consumes the requested bytes; short reads surface as `error.EndOfStream` through `tryNext`/`tryFillBytes` and panic on the infallible surface. |
| `ChaCha8Rng`, `ChaCha`, and `ChaCha20Rng` `init`, `initFromU64`, `addEntropy`, `fill` | Same byte stream for identical round count, seed, and entropy operation order. Each 512-byte refill runs the selected ChaCha round function with the current key and a zero nonce, retains the first 32 bytes as the next key, and emits the remaining 480 bytes. The first block matches standard ChaCha keystream bytes after that key prefix; later blocks follow the rekey chain rather than a counter-mode stream. |
| `Rng.uint`, `uintLessThan`, `uintAtMost`, integer ranges | Same output for fixed engine stream, integer type, and bounds on the same integer width. |
| `Rng.float`, `floatOpen`, `floatOpenClosed` | Same output for fixed engine stream and float type. |
| Deterministic point-mass helpers | Valid collapsed ranges, single-positive weighted-index/static weighted-sampler/weighted no-replacement/weighted-iterator choices, single-root/single-positive weighted trees, single-item choices, single-byte charsets, single-scalar Unicode charsets, and degenerate scalar/vector/multivariate distribution parameter sets return or fill their single possible value without consuming randomness. FisherF infinite-degree edge cases are intentionally excluded from this point-mass contract and instead follow the local `rand_distr` NaN-producing ChiSquared/Gamma draw shape. |
| `Rng.value` for bools, ints, floats, enums, tuples, arrays | Same output when all nested sampled types are stable. |
| `distributions.StandardUniform` | Scalar `sample` / `sampleFrom` mirrors `Rng.value` / `Rng.valueFrom`; primitive and vector fills mirror `Rng.fill` / `Rng.fillFrom`; compound array/tuple fills use repeated `Rng.valueFrom` draws. |
| `Rng.valueIter` / `valueIterFrom` | `nextValue` is scalar `value` sampling; `sizeHint` is unbounded (`usize.max..null`); `fill` preserves repeated-`nextValue` stream shape for packed-fill-sensitive types (`bool`, `f32`, `u8`, sub-64-bit integers, and structured values) and may use stream-equivalent bulk fill only for `f64`, 64-bit integers, and matching vectors. |
| `Rng.sampleIter` / `sampleIterFrom`; `distributions.sampleIter` / `sampleIterFrom` | `nextValue` follows the sampler's scalar `sample` / `sampleFrom` method; `sizeHint` is unbounded (`usize.max..null`); `fill` follows the sampler's bulk `fill` / `fillFrom` method when one exists, so high-volume iterator fills inherit each sampler's documented bulk stream policy. |
| `distributions.MappedSampler` | Same source-consumption shape as the wrapped sampler for scalar sample and mapped fill workflows; output is the wrapped sample transformed by the mapper. |
| `Rng.fill(u8, ...)` / `Rng.bytes` / `RngReader` adapters | Same byte stream for fixed engine stream; `RngReader` owns value sources, borrows pointer sources, and exposes the same infinite byte stream through `std.Io.Reader` reads, streams, and limited discards. |
| `seq.chooseIteratorHintedFrom` | For exact-size iterators exposing exact `sizeHint`, `len`, or `remaining`, the selected item is the item at one bounded random index from the current remaining length. For unhinted iterators it falls back to the stable reservoir `chooseIteratorFrom` stream shape. |
| `ascii.Charset` sampling and ASCII string aliases | Same bytes for fixed engine stream, charset bytes, and requested sample/append length. |
| `ascii.UnicodeCharset` sampling and UTF-8 string aliases | Same scalars and UTF-8 bytes for fixed engine stream, scalar set, and requested sample/append length; `maxUtf8Len()` and `utf8Capacity(length)` are stable functions of the scalar set and requested count. |
| `Rng.unicodeScalarFrom`, `Rng.fillUnicodeScalarFrom`, `Rng.unicodeScalarBatchFrom`, `Rng.unicodeScalarRangeLessThanFrom`, `Rng.unicodeScalarRangeAtMostFrom`, `Rng.fillUnicodeScalarRangeLessThanFrom`, `Rng.fillUnicodeScalarRangeAtMostFrom`, `Rng.unicodeScalarRangeLessThanBatchFrom`, `Rng.unicodeScalarRangeAtMostBatchFrom`, `ascii.unicodeScalarFrom`, `unicodeUtf8Capacity`, `unicodeUtf8AllocFrom`, `unicodeUtf8IntoFrom` | Same Unicode scalars and UTF-8 bytes for fixed engine stream and requested scalar count or scalar range; `fillUnicodeScalarFrom`, `unicodeScalarBatchFrom`, and scalar range fill/batch helpers preserve repeated scalar stream shape; `unicodeUtf8Capacity(len)` is stable as checked `len * 4`. |
| `seq.sampleIndicesU32`, `sampleIndexVec` with `.u32` backing | Same sampled index sequence for fixed engine stream, length, and amount. |

## Versioned Stable Outputs

These APIs are deterministic but may change when algorithms are intentionally
upgraded. Any change must be documented in the comparison/coverage notes.

| Area | Reason |
| --- | --- |
| Non-uniform distributions and reusable distribution samplers | Algorithms may be improved for statistical quality, endpoint semantics, or speed, as happened with Poisson, binomial, and floating-point inclusive uniform samplers. The S4-M1349..M1377 batch changed these versioned streams: exact 3×2 and single-column matrix vMF sampling, direct unit-circle tangent assembly for Watson/vMF, Zipf log-space acceptance, Weibull/Frechet/Pareto exp/log transforms, HIN binomial ziggurat exponentials plus Stirling/table log-factorials, Bingham `@log` acceptance and precomputed proposal scales, vectorized Student-t copula CDF, and the multinomial batch HIN cache. The S4-M1503 matrix-normal fix multiplies by the full Cholesky factors including the diagonals (the previous strict-lower product sampled unit variance for every covariance diagonal): `alea matrix normal 2x3` checksum `7176219298974891891` → `6414785259981111224` and `alea matrix t 2x3` `6077713839199129262` → `1707161836478801433`. The S4-M1550 HIN left-envelope `c/4` offset changes the small-`p` binomial stream (it removes the former `+0.015` mean bias by restoring envelope dominance below the mode). The S4-M1556 small-mean binomial walk replaces the waiting-time race with the same one-uniform inverse-CDF walk used by `CachedBinomial` for `mean < 16`, changing `Binomial` draws in that region and any multinomial/beta-binomial conditional that lands there. The S4-M1580 vector Kent `log I₀` series changes the vector Kent acceptance log-ratio for `a = ovalness·s² <= 1.5` lanes (accuracy improves from `3.3e-8` to `1.2e-11`; the scalar Kent path is unchanged). The S4-M1604 scalar Kent acceptance now uses the same 22-term `log I₀(a)` series as the vector path for `a <= 1.5` (acceptance error `3.3e-8` -> `1.2e-11`; the recorded scalar benchmark checksum is unchanged because no candidate landed in the `3e-8` threshold window). The S4-M1587 vector Kent uniform-angle branch draws the conditional angle from the uniform-circle proposal with the Exp(1) race whenever all lanes have `a < 1.5`, instead of the von Mises half-angle path (vector Kent checksum `16727813968867590217` -> `5861445844103430486`; the scalar Kent stream is unchanged). The S4-M1586 scalar-per-lane vector vMF change makes `VectorVonMisesFisher` draw each lane with the exact scalar S² vMF sampler instead of the packed SIMD loop (the target law is unchanged; `alea vector von mises-fisher f64x4 3d` checksum `15146673891782920812` -> `176802322559618529`). The S4-M1583 exact truncated-exponential marginal replaces the S² Wood rejection loop for `dim == 3`: `VonMisesFisher(T, 3)`, `VectorVonMisesFisher`, `Kent`, `VectorKent`, and the single-column matrix-vMF conditional now invert `w = −1 + log1p(U·(e^{2κ}−1))/κ` instead of sampling through the rational Wood proposal, so their consumed streams change while the target marginals are unchanged (`dim > 3` keeps Wood). The S4-M1507 Wishart fix computes the full Bartlett product `(L A)[i][j] = Σ_{j ≤ k ≤ i} L[i][k] A[k][j]` instead of truncating at `k ≤ min(i, j)` (the previous product dropped the below-diagonal Gaussian terms, so identity-scale draws were diagonal and non-diagonal scales understated off-diagonal covariance); `StaticWishart`/`Wishart` and the derived `StaticInverseWishart`/`InverseWishart` streams change for every scale and draw order. The S4-M1666 vector geometric fill hoist makes `VectorGeometric`/`VectorGeometricFailures` `fill`/`fillFrom` follow the dyadic packed-word kernel already used by `sampleFrom` instead of the scalar `geometricFrom`/`geometricFailuresFrom` lane loop, so dyadic-probability fill output changes while repeated `sample` is unchanged (`alea fillVectorGeometric f64x4` checksum `8389255.000` -> `8389752.000`). The S4-M1684 binomial fill extends the hoisted-CDF kernel to `129..1024` trials (binary search over the table) as a versioned bulk fill stream; `sample`/`sampleFrom` keep their existing per-vector paths, and extreme `p` whose `(1-p)^trials` underflows now fall back to the per-lane sampler in both paths (previously `VectorBinomial(128, 0.999)` returned `trials` for every lane). The S4-M1686 scalar `Poisson.fill`/`fillFrom` product method (`lambda < 12`) now builds the small CDF table once per call and draws with one uniform plus a binary search (exact product fallback for the truncated `1e-15` tail); scalar `sample` and `lambda >= 12` are unchanged. The S4-M1677/S4-M1682 hoisted-CDF kernel gives every `VectorPoisson` path for `lambda < 12` a versioned stream (one uniform per lane against a deterministic CDF table, with an exact product fallback for the truncated `1e-15` tail): fill builds the table once per slice, sample/sampleFrom rebuild it per call, so fill matches repeated sample; `lambda >= 12` is unchanged. The S4-M1675 dense vector zeta kernel gives f64 `VectorZeta` with exponent `1.25`, `1.5`, `2`, or `3` a versioned stream shape (one full-lane vector proposal plus scalar continuation for rejected lanes); the scalar `Zeta` stream, f32 vectors, and other exponents are unchanged. The S4-M1670 fix corrects the `Zeta.invCdf` fast path for exponent `1.25` (it returned `u^-1` instead of `u^-4`, so `P(X <= 1)` was `0.572` against the exact `0.218`): `Zeta`/`VectorZeta` exponent-1.25 streams change, while every other exponent keeps its stream and checksum. Each change is recorded in its `compare/results/s4-m13xx-*.md`, `s4-m15xx-*.md`, or `s4-m16xx-*.md` evidence file. |
